# 환경설정하기

ROS 2에서는 `워크스페이스(Workspace)`와 `소스 적용(Sourcing)`이 핵심입니다.

- **워크스페이스(Workspace):** 작업 중인 코드나 패키지들이 모여있는 '작업 공간'입니다. 여러 개의 워크스페이스를 연결하여 사용할 수 있습니다.
- **소스 적용(Sourcing):** 터미널이 ROS 2 환경을 인식하도록 '환경 설정'을 불러오는 과정입니다.

## Workspace

ROS 2에서 Workspace는 특정 버전의 '도구와 부품들이 담긴 공간'이라고 생각하시면 됩니다.

- **Underlay (기초 작업 공간):** ROS 2 설치 시 기본으로 생성되는 공간입니다. 여기에는 ROS 2를 실행하기 위한 필수 엔진과 표준 도구들이 들어있습니다. (마치 윈도우 순정 OS 같은 상태입니다.)
- **Overlay (상위 작업 공간):** 사용자가 직접 만든 코드나 외부에서 다운로드한 패키지가 담긴 공간입니다. 보통 코딩을 하는 폴더가 여기에 해당합니다.

ROS2는 Underlay 위에 Overlay를 올려서 사용하는 방식입니다. 만약 내가 기본 도구 중 하나를 수정해서Overlay에 넣어두면, 시스템은 Underlay에 있는 기본 도구 대신 **가장 위에 있는 도구(Overlay)**를 먼저 사용합니다.

이 덕분에 시스템 전체를 건드리지 않고도 안전하게 기능을 개발하거나 수정할 수 있습니다.

비슷한 시스템을 사용하는 프로그램이 있습니다. 예를 들면,

- Python의 가상 환경 (venv, Conda)
  - venv를 사용하면 OS에 깔린 라이브러리에 영향을 주지 않고, 프로젝트별로 필요한 라이브러리를 독립적으로 설치하고 관리할 수 있습니다. Workspace 와 비슷한 역할을 합니다.

- Node.js (npm / nvm) - 프런트엔드 개발 시 자주 사용하는 도구들도 비슷한 논리를 가집니다.
  - **nvm (Node Version Manager):** 여러 버전의 Node.js를 설치해두고 `nvm use` 명령으로 사용할 버전을 전환합니다. 이것도 내부적으로는 환경 변수를 바꿔주는 'Sourcing' 과정입니다.
  - **node_modules:** 전역(Global)에 설치된 패키지가 있어도, 현재 내 프로젝트 폴더(`node_modules`)에 있는 패키지를 우선해서 사용합니다. Workspace 는 node_modules 폴더와 같은 역할을 합니다.

## Sourcing(sourcing setup files)

터미널을 새로 열면 컴퓨터는 ROS 2 명령어가 어디 있는지 모르는 상태입니다. 이때 `source /opt/ros/humble/setup.bash` 같은 명령어를 입력하는 것은, ROS 2 명령어를 터미널이 인식하게 합니다.

- **Underlay 소싱:** `ros2`라는 명령어를 인식하게 만듭니다.
- **Overlay 소싱:** 내가 만든 `my_package`를 인식하게 만듭니다.

> Sourcing은 그 상자를 열어서 **사용 가능한 상태(PATH 설정)로 만드는 행위**입니다.

## 왜 매번 해야 하나

하나의 컴퓨터에 여러 버전의 ROS 2(예: Foxy, Humble)를 설치할 수 있기 때문입니다. 만약 자동으로 다 섞여버리면 터미널은 어떤 버전의 ROS 2 명령어를 써야할지 모릅니다.

그래서 터미널을 열 때마다 **"Humble 을 쓸 거야"** 혹은 "내가 개발 중인 이 폴더의 기능을 쓸 거야"라고 명시해 주는 과정이 필요한 것입니다. 이게 귀찮다면 `.bashrc` 파일에 등록해서 터미널을 열 때마다 자동으로 실행되게 만들기도 합니다.

## terminal 열때마다 자동으로 shell script 실행하기

원리는 간단합니다. .bashrc 에 `source /opt/ros/humble/setup.bash` 을 추가해주면 됩니다. 어떤 방식이던 상관이 없습니다. 대표적으로 2가지를 소개 하겠습니다.

1. \>> 오퍼레이터로 file에 이어서 쓰는 방식입니다. 이를 이용해서 .bachrc에 등록해줍니다.

```bash
echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc
```

2. vi(m), gedit 프로그램을 이용해서 .bashrc 파일에 등록해줍니다.

```vim

...

source /opt/ros/humble/setup.bash

```

이제 터미널을 열때마다 ros2 명령어를 사용할수 있게 됩니다.

### 환경변수 확인하기

```bash
printenv | grep -i ROS
```

```bash
ROS_VERSION=2
ROS_PYTHON_VERSION=3
ROS_DISTRO=humble
ROS_DOMAIN_ID=

```

ROS_DOMAIN_ID설정은 [여기](https://docs.ros.org/en/humble/Concepts/Intermediate/About-Domain-ID.html)를 참고해주세요.
