# 실행 인자(Arguments)와 C++ 포인터

ROS 2 노드는 프로그램의 진입점인 `main()` 함수를 통해 실행 인자를 전달받습니다. `main()` 함수의 매개변수인 `argc`와 `argv`가 메모리상에서 어떻게 포인터 구조로 관리되는지 알아보겠습니다.

---

## C++ `main()` 함수의 구조

C++ 프로그램은 실행될 때 외부 환경으로부터 입력값을 전달받기 위해 다음과 같은 구조의 `main()` 함수를 제공합니다.

```cpp
int main(int argc, char * argv[])
```

여기서 매개변수로 정의된 두 변수의 기본 개념은 다음과 같습니다.

- **`argc` (Argument Count)**: 프로그램 실행 시 전달된 실행 인자의 총 개수를 나타내는 정수형(`int`) 변수입니다. (실행 명령어 자체도 개수에 포함됩니다.)
- **`argv` (Argument Vector)**: 전달된 각각의 인자들이 문자열 형태로 저장되어 있는 주소(포인터)들의 배열입니다.

---

## 포인터 관점으로 보는 `argv`의 구조

C++에서 문자열은 문자의 배열이며, 메모리 관점에서는 문자(`char`)의 시작 주소를 가리키는 포인터인 `char *`로 표현됩니다.

따라서 `char * argv[]`는 **"char형 포인터를 원소로 갖는 배열"**을 의미하며, 이는 포인터 표기법을 통해 이중 포인터인 **`char ** argv`\*\*와 완전히 동일하게 취급됩니다.

### 메모리 구조 분석

터미널에서 프로그램을 다음과 같이 인자를 주어 실행했다고 가정해 봅시다.

```bash
./my_program -s 1.5 -c 3
```

이때 프로그램 내부적으로 설정되는 `argc`와 `argv`의 값과 포인터 구조는 다음과 같습니다.

- **`argc` = 5** (실행파일명 1개 + 인자 4개)

| 배열 인덱스 | 가리키는 문자열 (값) | 데이터 타입 | 메모리 의미                   |
| :---------- | :------------------- | :---------- | :---------------------------- |
| `argv[0]`   | `"my_program"`       | `char *`    | 실행 프로그램 이름의 주소     |
| `argv[1]`   | `"-s"`               | `char *`    | 첫 번째 옵션 문자열의 주소    |
| `argv[2]`   | `"1.5"`              | `char *`    | 첫 번째 옵션에 따른 값의 주소 |
| `argv[3]`   | `"-c"`               | `char *`    | 두 번째 옵션 문자열의 주소    |
| `argv[4]`   | `"3"`                | `char *`    | 두 번째 옵션에 따른 값의 주소 |

이를 조금 더 로우레벨 포인터 연산 관점으로 풀어보면 다음과 같이 매핑됩니다.

```cpp
argv = { "my_program", "-s", "1.5", "-c", "3" };
```

#### 1. 일차 참조 (`*argv`)

`argv`는 포인터 배열의 시작 주소를 가리키는 포인터(`char **`)입니다. 따라서 `argv`의 주소값을 한 번 참조(`dereference`)한 결과는 배열의 첫 번째 원소의 주소가 됩니다.

```cpp
*argv  // argv[0]과 동일하며, "my_program" 문자열의 시작 주소를 가리킵니다.
```

#### 2. 이차 참조 (`**argv`)

포인터 배열이 가리키는 곳의 주소값(즉, 첫 번째 문자열의 주소)으로 다시 한번 찾아가 문자 데이터 자체를 가리킵니다.

```cpp
**argv // argv[0][0]과 동일하며, 첫 문자열의 첫 번째 문자인 'm'을 나타냅니다.
```

이와 같이 `argv`는 단순히 데이터를 복사해서 들고 있는 배열이 아니라, **메모리에 적재된 인자 문자열들의 시작 주소를 이중 포인터 구조로 가리키는 참조 메커니즘**을 가지고 있습니다.

## ROS 2에서의 실행 인자 연동

ROS 2도 기본 C++ 표준을 준수하기 때문에 이 실행 인자 메커니즘을 100% 그대로 활용합니다.

ROS 2 C++ 노드 코드를 작성할 때 항상 마주치는 `main` 함수의 구조는 다음과 같습니다.

```cpp
int main(int argc, char * argv[]) {
    // 1. argc와 argv를 ROS 2 시스템 초기화 함수에 전달
    rclcpp::init(argc, argv);

    // 2. 노드 스핀 및 동작 실행
    rclcpp::spin(std::make_shared<MobileBaseController>());

    rclcpp::shutdown();
    return 0;
}
```

터미널에서 `--ros-args -p max_linear_velocity:=1.5`와 같은 특수한 ROS 2 실행 인자를 주어 기동하면, 이 명령행 매개변수들은 `argv` 포인터 배열에 고스란히 담겨 `rclcpp::init(argc, argv)`로 주입됩니다.

ROS 2의 내부 초기화 엔진은 `argv` 포인터 배열을 쭉 훑으며 `--ros-args` 키워드를 탐색 및 파싱하고, 파라미터 서버에 해당 값들을 바인딩하여 노드가 기동될 때 정상적으로 파라미터를 읽어갈 수 있도록 돕습니다.

## 마무리

실행 인자는 C++ 프로그램과 로봇 환경(OS)을 연결해 주는 기본적인 인터페이스입니다. 이중 포인터(`char **`)로 표현되는 `argv` 구조를 제대로 이해하면, ROS 2 노드가 파라미터를 파싱하는 물리적인 원리를 더욱 명확히 머릿속에 그릴 수 있습니다.
